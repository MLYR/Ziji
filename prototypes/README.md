# 资迹原型工作流

本目录保存 UI 评审原型与可复用生成提示词，不保存生产 Web/Mobile 代码。当前已确认基线入口为 `open-design/ziji-v1/index.html`，权威设计说明为 `doc/UI UX设计基线.md`。

## 1. 开始条件

1. 新原型、正式候选或交互语义变化需关联 `UI-DES-*`、`CHG-*` 或 `BUG-UI-*` 叶子任务；一次性探索和不改变语义的局部微调可挂靠当前原型任务。
2. 读取 PRD、RTM、UI/UX 基线以及相关领域/API 章节，先固定页面语义、数据状态和验收依据。
3. 选择 `prompts/` 中最接近的提示词。基线、可复用、晋升为正式候选或影响 UI/UX 语义的提示词必须保存；一次性探索、临时视觉实验和局部微调不强制新增 prompt 文件。

## 2. 工具与流程

- Codex 内生成可点击 HTML 原型默认使用 `huashu-design`，需要检索设计模式、配色或 UX 指南时可辅以 `ui-ux-pro-max`；必须完整执行 skill 的方向提案与评审流程。不得把图片生成 skill 当成交互原型工具。
- 用户指定 OpenDesign 或其他外部设计工具时，把 `prompts/ziji-v1-base.md` 全文放在前面，再紧接对应专项 prompt 全文，作为同一条完整请求提交。外部工具不可调用时，只交付这份组合 prompt 并将原型任务保持未完成。
- 新稿先落到 `prototypes/candidates/<任务ID>/`；评审通过后，才可按任务合并到 `open-design/ziji-v1/` 并更新入口和基线文档。
- `.artifact.json` 只作为原型生成元数据；外部 `.od-skills`、插件、缓存、登录态和会话文件不得纳入项目。

## 3. 生成禁止项

- 不得覆盖已确认基线来绕过候选评审。
- 不得照搬支付宝等第三方品牌、商标、文案或像素级视觉资产。
- 不得展示 V1 范围外入口，不得把 Tushare 盘后数据写成实时行情。
- 不得用伪造的“0 元”“0%”代替未加载、待数据、无持仓或估值不完整。
- 不得把原型 HTML/CSS/JS 直接复制进生产工程，也不得从演示数据反推账务规则。

## 4. 评审与基线晋升

候选稿至少验证：Web 1440px、Mobile 390px、深浅主题、无横向溢出、关键流程可完成、加载/空/错误/无权限/离线/冲突可恢复、状态不只靠颜色、键盘焦点可见，并按 `doc/UI UX设计基线.md`§7 使用至少一种读屏方式检查关键流程。投资收益和总资产日历还必须覆盖各自 prompt 中的全部日期状态与明细归因。

只有在产品确认、`doc/UI UX设计基线.md`§7 门禁完成、台账记录证据后，候选稿才能成为生产实现依据。原型通过不等于生产页面通过无障碍或端到端验收。

## 5. 提示词索引

- `prompts/ziji-v1-base.md`：所有资迹原型共用上下文、视觉语言和输出约束。
- `prompts/investment-return-calendar.md`：投资收益日历专项 prompt，使用时拼接在共用 prompt 后。
- `prompts/total-asset-calendar.md`：总资产/净资产变化日历专项 prompt，使用时拼接在共用 prompt 后。
