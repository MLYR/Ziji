# CI 分层说明

本文说明本仓库的**变更感知 CI** 模型：哪些检查固定跑在每个拉取请求，哪些按路径触发，哪些留给批次/发布门禁。

实现入口：

- `.github/workflows/ci.yml`
- `scripts/detect-change-risk.mjs`
- `workflow-security.yml`（单独守护 CI 安全门禁契约，**不得削弱**）

文中的 `backend`、`web`、作业显示名等英文，均为工作流/脚本中的**固定标识**，便于对照 GitHub Actions 界面；说明文字一律用中文。

## 三层门禁

| 层级 | 触发时机 | 目标 | 本仓库现状 |
| --- | --- | --- | --- |
| 拉取请求门禁 | 每个指向 `main` 的拉取请求（以及手动 `workflow_dispatch`） | 快速、按变更面收敛；失败即阻断合并 | `ci.yml`：变更检测 + 路径作业 + 安全快检/深检 |
| 批次门禁 | 功能批次收口、联调或定期验证 | 覆盖跨端与重型验证，不绑定每个拉取请求 | 端到端、Maestro、性能、真实供应商冒烟**不在** `ci.yml` 固定执行 |
| 发布门禁 | 发布前或主干发布流程 | 全量回归与供应链深扫等更高证据 | 依赖批次结果 + 供应链相关变更触发的安全深检；手动工作流可拉高风险面 |

## 每个拉取请求上固定发生什么

每个拉取请求都会先跑变更检测作业（界面名：`Detect change risk`），再按布尔输出决定后续步骤：

1. **变更检测（必跑）**：调用 `detect-change-risk`，并校验所有输出为严格的 `true` / `false`。
2. **安全快检（默认）**：当 `security_deep` 为 `false` 时，只做密钥类快检。
3. **路径作业（按需）**：仅当对应输出为 `true` 时，才对 `backend` / `web` / `mobile` / `api`（契约）执行实质步骤；否则打印 `not applicable`（不适用）后结束。
4. **安全深检（按需）**：仅当供应链相关路径变更（或手动运行）使 `security_deep` 为 `true` 时，执行全量供应链扫描。

未改到的面不会被强行跑重型检查。纯文档类拉取请求（除下方「迁移」特例外）通常只保留变更检测 + 安全快检。

## 变更检测输出与作业对应关系

| 输出名（脚本） | 主要判定路径 | 驱动的作业 / 行为 |
| --- | --- | --- |
| `backend` | `backend/` 目录，或迁移相关，或手动运行 | 后端检查：非深路径只编译；深路径跑完整测试 |
| `backend_deep` | Flyway、数据库设计文档、核心域 Java、`backend` 测试，或手动运行 | 与 `backend` 组合：决定「编译」还是「完整测试」 |
| `web` | `web/` 目录，或共享类型与锁文件，或手动运行 | Web 检查 |
| `mobile` | `mobile/` 目录，或共享类型与锁文件，或手动运行 | Mobile 检查（类型/配置/单元；不含 Maestro） |
| `api` | `openapi/`、`api-types`、Controller/DTO 等相关路径，或手动运行 | OpenAPI 契约检查 |
| `migration` | Flyway 目录或数据库设计文档 | 不单独开作业；已并入 `backend` 与 `backend_deep` |
| `security_deep` | 依赖清单、Maven 入口、`security/`、扫描配置、工作流等，或手动运行 | `false` 为快检；`true` 为全量供应链扫描 |

补充约定：

- 手动 `workflow_dispatch` 视为高风险排查面：多数开关置为 `true`，便于一次拉满检查。
- 只改普通文档（且不是数据库设计文档）时，不应把 `backend` / `web` / `mobile` 置为 `true`。
- `workflow-security` 会校验拉取请求头与受信基线中 `changes`、`backend`、`security` 等作业契约一致；禁止削弱扫描或「失败即阻断」策略。

## 明确不在每个拉取请求固定执行

以下能力属于批次或发布证据，而不是当前 `ci.yml` 的必跑步骤：

- 浏览器端到端套件
- Maestro 原生界面自动化
- 性能基准与压测
- 真实第三方供应商联调冒烟

Mobile 作业注释已写明：Maestro 需要原生模拟器；基础 CI 只做类型、配置与单元检查。

## 维护提示

- 增删路径规则时，先改 `detect-change-risk`，再确认 `ci.yml` 的条件仍消费同一组输出名。
- 调整安全扫描入口、受信源列表或安全作业条件时，必须同时满足 `workflow-security` 契约，避免拉取请求自行改扫描器后自通过。
- 若未来需要独立的「迁移提示」步骤，应作为契约兼容的增量，且不削弱「失败即阻断」；当前 `backend_deep` 已覆盖 Flyway。
